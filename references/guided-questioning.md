# Guided questioning

Use this protocol whenever the author must make a creative decision or says they have no idea.

## Default interaction

- Ask one high-leverage question per turn; ask at most two when the decisions are tightly coupled.
- If the author already has a clear answer, refine it instead of forcing a menu.
- If the author is uncertain, offer 3–5 genuinely different options grounded in confirmed project facts.
- Explain each option's likely effect on plot engine, character arc, tone, pacing, or later constraints.
- Mark one recommendation when evidence supports it and explain why. A recommendation is not a decision.
- Always allow `mix`, `custom answer`, and `decide later` without treating them as failures.
- Accept answers outside the menu. Do not keep the author inside an artificial decision tree.
- Record rejected directions so they are not repeatedly suggested.

## Option quality

Vary the underlying dramatic mechanism, not just names or surface details. For example, alternatives for a protagonist's drive could be restoration, proof of worth, protection, truth-seeking, escape, or transformation. Avoid four cosmetic variants of the same motive.

When little is known, diversify options across:

- external objective;
- internal need;
- relationship pressure;
- opposing force;
- cost of failure;
- thematic implication.

If all options are rejected, ask what felt wrong about them, preserve the negative preference, and generate a materially different set.

## Interaction intensities

### Inspiration

Use when the author has no concept. Offer concrete possibilities with low pressure. Do not begin by attacking missing logic.

### Standard

Use by default. Ask one question, explain options and consequences, then advance after confirmation.

### Fast

Use only when the author requests batching. Ask 3–5 numbered decisions at once, each with concise options. Do not use for interdependent structural decisions.

### Deep dive

Use when one premise, motivation, turn, or rule must be resolved before progress. Continue questioning that issue, but stop when it is coherent enough for the current outline stage.

## Embedded grilling behavior

Grilling is a focused interview, not hostility. When an answer remains vague, test it with questions such as:

- Why must this happen now?
- Why does this character choose this path rather than the easier one?
- What changes if this event is removed?
- What would the most competent opponent do in response?
- What price makes the choice irreversible?
- Which confirmed fact supports this reveal?

Do not grill an early seed as if it were a finished outline. Increase pressure at stage boundaries and when the author explicitly asks for it.

## Response pattern

Use a compact form:

```markdown
### 需要决定：主角为何必须今晚离开？

- **A. 追捕者已经锁定住处** — 改动小，直接增加紧迫感。
- **B. 主角必须抢先找到证人** — 增强主动性，并推动悬疑线。
- **C. 同伴可能已经背叛他** — 强化关系冲突，但需要提前铺垫。
- **D. 混合、自定义或暂缓决定**

**推荐 B**：它同时解决紧迫性和主角主动性。
```

After the author chooses, state whether the answer is a candidate or confirmed decision and note the most important downstream consequence.
